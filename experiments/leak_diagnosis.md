# 1차 시도 진단 — "mAP 0.995인데 왜 실패인가"

측정일 2026-08-15 · 대상 `experiments/legacy_runs/` 19개 run + 로컬 데이터셋 8종

재현: `python3 scripts/collect_runs.py`, `python3 scripts/check_leakage.py <데이터셋 경로>`

---

## 요약

1차 시도는 19회 학습에서 mAP50 0.54~0.995를 기록했다. 대부분이 0.99대였음에도 실제 영상에 적용하면 성능이 나오지 않았다. 원인은 세 가지이며, **모두 모델이 아니라 데이터에 있다.**

| # | 원인 | 근거 |
|---|---|---|
| 1 | 학습 데이터의 **36~72%가 Gemini 생성 합성 이미지** | 아래 표 |
| 2 | val 세트가 **원본 9~16장** | 아래 표 |
| 3 | 실사 프레임의 **출처 영상이 1개** | 원본 영상 `battery_source.mp4` 단일 |

> **처음 세운 가설(train/val 누수)은 틀렸다.** base 이름 기준으로 검사한 결과 같은 원본이 train과 val 양쪽에 들어간 사례는 **0건**이다. Roboflow 분할 자체는 깨끗했다. 문제는 분할이 아니라 **분할되는 데이터의 성질**이었다.

---

## 근거 1 — 합성 이미지 비중

`Gemini_Generated_Image_*` 파일명으로 식별. `battery_vision2/README.md` 의 기술 스택에도 "이미지 증강: Gemini (합성 학습 데이터 생성)"으로 명시돼 있다.

| 데이터셋 | train | valid | 합성 비중 |
|---|---|---|---:|
| `Battery vision.slitting.yolov8` | 60장 / 20원본 | 5장 / 5원본 | **72%** |
| `battery-process-detection.v7i` | — | 10장 / 10원본 | **70%** |
| `Battery vision.coating.yolov8` | 114장 / 38원본 | 9장 / 9원본 | **60%** |
| `Battery vision.v4i.yolov8` | 195장 / 65원본 | 16장 / 16원본 | **57%** |
| `Battery vision.v7i.yolov8` | 159장 / 53원본 | 13장 / 13원본 | 50% |
| `Battery vision.v6i.yolov8` | 147장 / 49원본 | 12장 / 12원본 | 46% |
| `Battery vision.v9i.yolov8` | 126장 / 42원본 | 10장 / 10원본 | 42% |
| `Battery vision.v12i.yolov8` | 105장 / 35원본 | 9장 / 9원본 | 36% |
| `v15_raw` (9클래스) | 408장 / 136원본 | 0장 | 16% |

**해석.** 생성 이미지끼리는 분포가 서로 닮아 있다. train과 val이 모두 합성 이미지로 채워지면 모델은 "합성 이미지에서 설비를 찾는 문제"를 풀게 되고 그 문제는 쉽다. 실제 공정 영상 프레임은 조명·모션블러·occlusion·저해상도가 전혀 다르므로 성능이 무너진다.

**즉 mAP 0.995는 거짓말이 아니라, 다른 문제를 푼 정답이다.**

## 근거 2 — val 세트 크기

val 원본이 9~16장이다. 클래스가 3개면 클래스당 3~5장으로 채점한 셈이다. 이 크기에서 mAP 0.995와 0.90의 차이는 이미지 한 장 차이로 뒤집힌다. **지표로 쓸 수 없다.**

`v15_raw`(RunPod 학습에 쓰인 9클래스 데이터셋)는 아예 **val이 0장**이다 (Roboflow 100% train 분할). 그럼에도 `experiments/runpod_v12/results.csv` 에는 val mAP 0.993이 기록돼 있다 → 학습 데이터로 채점한 값이다.

## 근거 3 — 실사 프레임의 단일 출처

실사 프레임은 전부 `battery_source.mp4` 한 개에서 나왔다. 같은 영상 프레임은 어떻게 분할해도 카메라·조명·설비가 동일하다. **"미학습 영상 성능"을 측정할 방법이 원리적으로 없었다.**

## 학습 이력에서 관찰되는 패턴

`experiments/history.csv` 전체 19건 중 발췌:

| run | 데이터셋 | mAP50 | mAP50-95 | imgsz |
|---|---|---:|---:|---:|
| battery_v4-2 | v16i (Colab) | 0.995 | 0.946 | 640 |
| coating_v2~v5 | coating 계열 (합성 60%) | 0.995 | 0.638~0.671 | 512 |
| slitting_v1~v3-2 | v1i~v3i (합성 72%) | 0.995 | 0.593~0.613 | 512 |
| battery_v3-4 | v15i (Colab) | 0.692 | 0.461 | 640 |
| battery_v3-2 | v13i (Colab) | 0.661 | 0.379 | 640 |
| battery_v3-3 | v14i (Colab) | 0.542 | 0.317 | 640 |

합성 비중이 높은 데이터셋일수록 mAP50이 0.995에 붙는다. 반대로 `battery_v3` 계열(v13i~v15i)만 0.54~0.69로 떨어지는데, 이들은 Colab에서 학습돼 로컬에 데이터셋이 없어 합성 비중을 직접 확인하지 못했다. **다만 `v15_raw`(v15i의 Roboflow 재수출본)의 합성 비중이 16%로 급감한 것을 보면, v13i~v15i 시점에 실사 프레임 비중을 크게 늘렸을 가능성이 높다.**

그렇다면 **0.54~0.69가 이 프로젝트의 진짜 성적**이고, 0.995는 합성 데이터가 만든 착시다.

### 남은 확인 사항

- v13i~v16i 데이터셋을 Colab Drive에서 회수해 합성 비중을 직접 측정하면 위 가설이 확정된다
- 회수가 어려우면 Phase 1에서 `v15_raw`(합성 16%)를 영상 단위로 재분할해 측정하는 것으로 대체한다

## 이번 재설계에 반영할 것

| 진단 | 대응 |
|---|---|
| 합성 이미지 의존 | **Gemini 생성 이미지를 학습 데이터에서 전면 배제.** 실사 프레임만 사용 |
| val 세트 과소 | val 원본 100장 이상 확보. 그 전까지의 mAP는 참고치로만 표기 |
| 단일 출처 영상 | 영상 3~5개로 확장, **train·val·test를 영상 단위로 분할** |
| 측정 신뢰성 | `build_splits.py` 에 분할 간 교집합 0 을 `assert` 로 박아넣는다 |

> `data/frames/v1_unlabeled/` 에 실사 프레임 1,055장이 이미 정리돼 있다. 합성 이미지를 버려도 실사 데이터는 오히려 기존 학습에 쓰인 것보다 많다.
